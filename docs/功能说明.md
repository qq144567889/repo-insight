# 功能说明

按模块列出全部功能、行为与边界。编号沿用开发规格，便于对照 Issue。

## 1. 仓库识别（F-01）

| 项 | 说明 |
|---|---|
| 识别规则 | 解析当前标签页 URL，取 `owner/repo`；`/tree/`、`/issues/` 等后缀页面同样识别 |
| 保留字白名单 | `settings`、`notifications`、`users`、`apps`、`orgs`、`marketplace`、`topics`、`explore` 等一级路径一律判为非仓库页 |
| 域名校验 | 仅接受 `github.com` / `www.github.com`，`github.com.evil.example` 这类伪装域名被拒绝 |
| 非仓库页 | 弹窗提示「未识别到仓库」并禁用生成按钮 |

## 2. 仓库数据抓取（F-02 ~ F-04）

- 依次请求：元信息 → README（raw，失败回退 JSON + `TextDecoder` 解码）→ 语言占比 → 根目录文件列表；
- 4 个接口并行（`Promise.allSettled`），单点失败不阻断整体；
- **私有仓库**：拿到元信息后立刻判断 `private`，未获确认则**不再读取 README**，任何内容都不离开本机；
- **缓存**：ETag 条件请求 + 6 小时本地缓存；命中 304 时 GitHub 不扣配额；私有仓库不写缓存；
- 超时与限流：全部请求 20s 超时；403 先看 `x-ratelimit-remaining`，再区分二级限流 / 被拒。

## 3. 文档生成（F-05 / F-06）

优先级：**模型生成 → 失败或未配置 → 本地模板降级**。

| 项 | 说明 |
|---|---|
| 流式输出 | 走 SSE，边生成边渲染；服务商忽略 `stream` 时自动回退为一次性解析 |
| 模型参数 | 标准档 `max_tokens=4000`，精简档 2000；对 `max_tokens` → `max_completion_tokens` 的差异做一次自动重试 |
| 降级模板 | 输出仓库信息、技术栈探测、许可证提示与部署骨架，标题标注「本地模板 · 未接入 LLM」 |
| 结构自检 | 校验六个必需章节是否存在、顺序是否正确，缺失时在预览区提示 |
| 后处理 | 补齐 AI 标识行、许可证风险条目（并入风险章节）、溯源注释 |

## 4. 预览与导出（F-07 ~ F-09）

- 预览区按 Markdown 排版渲染（标题 / 列表 / 引用 / 代码块 / 表格 / 链接）；
- **复制与下载得到的仍是原始 Markdown**，与预览内容一致；
- 下载文件名 `{repo}-解读.md`，文件名经过非法字符清洗。

## 5. 模型配置（F-10 / F-11）

- 预设：DeepSeek / OpenAI / 智谱 / Moonshot / 通义 / Ollama / 自定义（OpenAI 兼容）；
- 自定义 Base URL：必须是 https（本机地址可用 http），保存时**运行时申请该域名权限**；
- 「测试连接」发送最小请求，成功显示模型名与耗时；
- API Key 与 Token 只存本机，界面仅回显掩码。

## 6. 限流与错误（F-12）

错误码统一为 `{code, message, hint, retryable, detail}`，`hint` 给出可操作建议（例如「配置 GitHub Token 提升至 5000 次/小时」）。完整映射见 `lib/errors.js`。

## 7. 历史记录

- 生成成功后自动归档（可关闭），最多 20 条，**同一仓库只保留最新一条**；
- 列表只返回元信息，点击时才取全文（懒加载）；
- 私有仓库默认不写入历史（可显式开启）；
- 支持单条删除、一键清空、导出 JSON 备份（**不含任何密钥**）。

## 8. 数据管理

设置页「数据与隐私」显示存储占用、历史条数、缓存条数、存储项与密钥配置状态，并提供：清空历史 / 清除缓存 / 清除所有本地数据。

## 9. 自动弹出

打开仓库页且页面加载完成时自动弹出弹窗；同一标签页同一地址只弹一次；无法自动弹出时（例如窗口未聚焦）改为扩展图标角标提示；可在设置页关闭。

## 10. 风险评估（部署前）

**高风险规则**：管道执行 shell（curl/wget \| bash）、读取凭据文件（`.aws/credentials`、`.ssh/`、`id_rsa`…）、修改 PATH / 启动项 / 计划任务、提权与危险删除、关闭安全校验、编码载荷执行、全局静默安装依赖。

**中风险规则**：需要第三方 API Key、依赖大量第三方包、Star 少于 50、监听宿主机端口。

**另外两类硬告警**：README 中出现疑似硬编码密钥；仓库疑似提交了真实 `.env`。

## 11. 部署方案

- **方案 A 沙箱**：`.devcontainer.json` → Codespaces；`package.json` → StackBlitz / Gitpod / Codespaces；Dockerfile/compose → Gitpod / Codespaces；嵌入式 / 固件 → 明确提示不支持；
- **方案 B 本地**：强制「风险评估 → 环境预检 → 勾选确认」三步，然后生成部署章节与脚本；
- 部署脚本默认容器隔离，支持 `--dry-run` / `--host`（二次确认）/ `--clean`。

详见 [部署方案](部署方案.md)。

## 12. 界面

- 深浅色跟随系统，三个界面共用 `theme.css`；
- 弹窗面板与窗口同色（不露白角、无外框）；
- 标题、按钮、标签页、历史条目样式统一。

## 13. 边界与不做的事

| 不做 | 原因 |
|---|---|
| 执行系统命令 | Chrome 扩展没有该权限 |
| 代码级静态分析 / CVE 扫描 | 规则文本匹配，不做 AST 与依赖漏洞库 |
| 云端存储与团队协作 | 无服务端，零遥测 |
| 保证模型输出正确 | 由 AI 生成，文档内固定标注提示 |
