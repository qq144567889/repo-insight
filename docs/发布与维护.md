## 二、功能标签（Topics）

在仓库页右上角 ⚙ → **Topics** 粘贴下面这组（GitHub 最多 20 个，按重要度从前往后）：

```
chrome-extension
manifest-v3
github-tool
ai
llm
deepseek
ollama
code-analysis
developer-tools
markdown
privacy
local-first
productivity
open-source-tool
repository-analysis

```

用命令行一次加完：

```bash
gh repo edit --add-topic chrome-extension,manifest-v3,github-tool,ai,llm,deepseek,ollama,code-analysis,developer-tools,markdown,privacy,local-first,productivity,open-source-tool,repository-analysis,documentation,self-hosted,no-dependencies
```

> 标签的作用：GitHub 搜索结果与「Explore → Topics」页面会按标签推荐；`chrome-extension`、`ai`、`developer-tools` 这几个大标签流量最大，`local-first`、`privacy` 这类标签能带来更精准的用户。

## 三、首次推送

### 方式 A：网络可直连 github.com（推荐）

```bash
cd repo-insight
bash tools/push.sh            # 自动：检查 gh 登录 → 提交 → 建仓 → 推送 → 加标签
```

等价的手动步骤：

```bash
git init && git add -A && git commit -m "feat: Repo Insight v0.5.4 首次开源"
git branch -M main
gh repo create repo-insight --public --source=. --push --description "一键把 GitHub 仓库变成结构化解读 + 部署方案（Chrome MV3 扩展，隐私优先，支持本地 Ollama）"
gh repo edit --add-topic chrome-extension,manifest-v3,github-tool,ai,llm,deepseek,ollama,code-analysis,developer-tools,markdown,privacy,local-first,productivity,repository-analysis,documentation,no-dependencies
```

### 方式 B：github.com 被墙、但 api.github.com 可达

用 Git Data API 直接建仓并推送（不需要 git 与 github.com）：

```bash
# 先在浏览器打开 https://github.com/settings/tokens 创建 classic token（勾选 public_repo 即可）
GITHUB_TOKEN=你粘贴的token node tools/push-via-api.mjs
```

脚本会自动：校验 token → 建仓（已存在则跳过）→ 逐个上传文件 → 建 commit 与 main 分支 → 设置功能标签 → 回填仓库描述。

推送后补上标签（见上一节）。

## 五、新增功能时的检查清单

- [ ] 版本号：`manifest.json`、`lib/template.js` 的 `EXTENSION_VERSION` 同步递增；
- [ ] 文档：README 的「功能特性」「文件结构」「路线图」是否需要更新；
- [ ] `CHANGELOG.md` 增加一条；
- [ ] 新增文件保留头部署名注释（LICENSE 第 2.2 条）；
- [ ] 运行三层验证；
- [ ] 运行 `bash tools/package.sh`，确认自检通过。

## 六、署名保护要点（不要动）

以下位置包含署名，属于授权条款的一部分，**改动会让 LICENSE 失效**：

1. 所有源码文件头部注释；
2. `manifest.json` 的 `author` 与 `homepage_url`；
3. 弹窗底部、设置页底部、部署页底部的 `© Yang YIZHU · 禁止商业售卖`；
4. 生成文档末尾的 `author: Yang YIZHU | license: 禁止商业售卖`；
5. `LICENSE`、`NOTICE.md`、`TAMPER_NOTICE.txt`、`README.md` 尾部署名段。

## 七、如果要做 Chrome Web Store

1. 已具备：`privacy.html`（隐私政策内容）、权限最小化、无远程代码、无遥测；
2. 需要准备：隐私政策的**公网可访问链接**（可把 `privacy.html` 部署到 GitHub Pages）、1280×800 或 640×400 截图、详细描述、开发者账号（一次性 $5）；
3. 注意：Store 后台「数据使用」需勾选收集「身份验证信息（API Key）」与「网站内容（仓库 README）」，并声明不用于广告、不售卖；
4. 由于本项目为「禁止商业售卖」的自定义许可，上架免费扩展没有问题，但**不能用于付费售卖**。
