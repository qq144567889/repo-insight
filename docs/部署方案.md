# 部署方案说明

生成解读后，点弹窗里的「🚀 部署」打开部署页，三选一：

| 方案 | 面向谁 | 是否需要装东西 |
|---|---|---|
| 🔬 **A：一键沙箱体验** | 所有人（推荐先用这个） | 什么都不用装 |
| 🐣 **C：新手快捷本地部署** | 完全零基础、没碰过命令行 | 一条命令或双击一个文件 |
| 💻 **B：一键本地部署** | 懂一点技术、想要完整预检报告 | 需要自己看依赖 |

> **前提**：Chrome 扩展不能执行系统命令。所以「一键」= 一键生成方案与**可运行脚本**，部署页不会自动运行任何命令。

## 方案 C：新手快捷本地部署

面向完全零基础用户的方案，**全程口语化**，不出现 Docker / Node / git 之类的名词轰炸。

### 用户只需要做三件事

1. 打开「黑窗口」（Mac：Command+空格 搜「终端」；Windows：Win 键搜 PowerShell）；
2. 把插件给的一整行命令复制进去，按回车；
3. 等着——第一次 2～10 分钟，看到 `http://localhost:3000` 且浏览器自动打开就成功了。

### 提供两种做法

| 做法 | 适合 | 说明 |
|---|---|---|
| **下载双击脚本** | 完全不想碰命令行 | macOS 下载 `.command`、Windows 下载 `.bat`，项目与端口已预先填好，双击即运行 |
| **复制一行命令** | 会用一点点电脑 | 一行完成「下载安装脚本 → 运行」，两步写在同一行（**不是** `curl \| bash`，脚本可先保存再查看） |

### 脚本对新手做的保护

- **优先 Docker 隔离运行**，并用人话告诉用户"跑在隔离小盒子里，不碰你的系统"；
- **没有 Docker 时先询问**，给出官方下载页，**不会偷偷安装**任何东西；
- 项目只下载到 `~/RepoInsight/`（Windows 为 `%USERPROFILE%\RepoInsight\`），想删就删；
- 结束时会打印"怎么关掉""怎么彻底删干净""出问题去哪反馈"；
- 附带配套的清理命令：`bash install.sh --clean owner/repo`（Windows：`install.bat clean owner/repo`）。

### 风险提示的口语化处理

不再是"高风险命中规则 3 条"，而是一句人话，例如：

> ⚠️ 这个项目的安装脚本里有一些**比较危险的操作**（比如下载东西直接执行、读写系统配置）。新手强烈建议先用「方案 A 沙箱体验」。

同时保留一个轻量确认勾选（"我看懂了：这个项目会用我电脑的权限运行"），不勾选不能下载脚本。

### 通用安装脚本

仓库根目录提供两个**通用**脚本，任何仓库都能用，内容开源可审计：

```bash
bash install.sh 作者名/仓库名 [端口]        # macOS / Linux
install.bat 作者名/仓库名 [端口]            # Windows
bash install.sh --clean 作者名/仓库名       # 清理
```

扩展下载的"双击脚本"就是在它们基础上预填了项目与端口，**逻辑只有一份**。

## 方案 A：一键沙箱体验（推荐）

按仓库特征识别沙箱载体，给出直达链接：

| 仓库特征 | 识别结果 | 链接 |
|---|---|---|
| `.devcontainer.json` | GitHub Codespaces | `https://codespaces.new/{owner}/{repo}` + Gitpod |
| `package.json` | StackBlitz / Gitpod / Codespaces | `https://stackblitz.com/github/{owner}/{repo}` 等 |
| Dockerfile / compose | Gitpod / Codespaces | `https://gitpod.io/#https://github.com/{owner}/{repo}` |
| 嵌入式 / 固件（`.ino`、`platformio.ini`、`idf.py`） | 不支持浏览器沙箱 | 明确提示需要本地工具链与硬件烧录 |
| 其它 | 通用 Linux 沙箱 | Gitpod / Codespaces |

嵌入式判断被放在**最前**：PlatformIO 项目通常同时带 `package.json`，若按顺序判断会被误认成 Web 项目。

沙箱限制会在页面上明确列出（无法操控本地硬件、免费实例会休眠、密钥请用平台 Secret、不要粘贴自己的 Key）。

## 方案 B：一键本地部署（受控执行）

### 三重闸门

1. **自动风险评估**（纯规则，不调用模型）
   - 高风险：管道执行 shell、读取凭据文件、修改 PATH / 启动项 / 计划任务、提权与危险删除、关闭安全校验、编码载荷执行、全局静默安装依赖；
   - 中风险：需要第三方 API Key、依赖大量第三方包、Star 少于 50、监听宿主机端口；
   - 硬告警：README 含疑似硬编码密钥、疑似提交真实 `.env`；
   - 命中会给出**具体证据行**（已脱敏）。
2. **本机环境预检**
   - 生成只读脚本 `repo-insight-detect-env.sh`：不安装、不修改任何文件，只输出一行 JSON；
   - 检测项：Node / npm / Python / Docker / git / 端口占用 / 磁盘剩余 / 网络可达性；
   - 粘贴 JSON 后生成依赖表格，缺失项附官方安装指引。
3. **强制勾选确认**
   - 未勾选时「生成本地部署章节」按钮禁用；
   - 高风险时勾选文案变为「我已知晓高风险，仍要继续」。

### 生成的部署脚本

默认容器隔离，脚本头部即为可读的说明与参数列表：

```bash
bash repo-insight-deploy.sh              # 默认：Docker 容器内运行
bash repo-insight-deploy.sh --dry-run    # 只打印将执行的命令
bash repo-insight-deploy.sh --host       # 直接在宿主机运行（需输入 yes 二次确认）
bash repo-insight-deploy.sh --clean      # 删除容器、数据卷与克隆目录
bash repo-insight-deploy.sh --port=8080  # 指定端口
```

脚本设计要点：

- 默认 `docker run --rm -it`，只挂载专用数据卷与克隆目录，不挂载宿主敏感路径；
- 不使用 `eval`，所有命令通过 `run()` 包装，`--dry-run` 下只打印；
- 不写死任何密钥，API Key 通过环境变量传入；
- 克隆目录固定在 `~/.repo-insight/<repo>`，清理时一并删除；
- 缺少 Docker 时给出安装指引并退出，不会静默失败。

## 常见问题

**Q：脚本会自己跑吗？** 不会，需要你审阅后手动执行。

**Q：为什么默认用 Docker？** 本地部署最大的风险是未知脚本拿到你的全部权限，容器是成本最低的隔离手段。

**Q：环境预检为什么要跑脚本？** 扩展没有权限读取本机环境，只能生成只读脚本让用户执行并回传结果。脚本内容可审计（只做 `command -v` 与版本查询）。

**Q：风险评估能替代人工审计吗？** 不能。它是静态规则匹配，覆盖不了运行时行为，高风险项目请先在沙箱或容器中验证。
