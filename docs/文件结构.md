# 文件结构说明

```
repo-insight/
├── manifest.json              # MV3 清单：权限、入口、图标、本地化
├── background.js              # Service Worker：消息路由、抓取编排、自动弹出、历史写入
├── popup.html / popup.js      # 弹窗：识别仓库、生成、预览、复制/下载、历史标签页
├── options.html / options.js  # 设置页：模型、Token、输出、交互、隐私与数据
├── deploy.html / deploy.js    # 部署页：沙箱方案 / 本地部署方案
├── privacy.html               # 隐私政策（扩展内可打开，也可作为上架材料）
├── theme.css                  # 深浅色主题变量（三个界面共用）
├── styles.css                 # 弹窗布局与组件样式
├── lib/                       # 核心模块，纯 ES Module，零依赖
├── _locales/{zh_CN,en}/       # 国际化文案
├── icons/                     # 16 / 48 / 128 图标
├── docs/                      # 文档与截图（不参与扩展运行）
├── tools/                     # 图标生成、打包脚本（不随扩展分发）
├── LICENSE / NOTICE.md        # 授权与署名（不得移除）
└── TAMPER_NOTICE.txt          # 发行包内的署名声明
```

## lib/ 模块职责

| 文件 | 职责 | 关键点 |
|---|---|---|
| `url.js` | 解析当前页面是否为 GitHub 仓库页 | 保留字白名单 + `hostname` 精确匹配，拦截伪装域名 |
| `github.js` | GitHub REST 抓取 | 顺序取元信息（用于私有仓库守卫）→ 并发取 README/语言/文件列表；限流分流、20s 超时、ETag 缓存 |
| `llm.js` | OpenAI 兼容模型调用 | `callLLM`（非流式）与 `streamLLM`（SSE）；`max_tokens` → `max_completion_tokens` 自动重试；忽略 `stream` 时回退解析 |
| `prompt.js` | 提示词与用户内容组装 | 版本号常量；README 用 `<untrusted_readme>` 包裹；含防注入、命令安全、溯源、许可证四类硬性条款 |
| `template.js` | 输出模板与后处理 | 六个必需章节、结构自检、降级模板、许可证分级、AI 标识与溯源注释 |
| `risk.js` | 部署前风险评估 | 8 条高风险 + 4 条中风险规则、密钥扫描、`.env` 告警、沙箱载体识别、隔离建议 |
| `deploy.js` | 部署方案生成 | 部署脚本（容器优先、`--dry-run`/`--host`/`--clean`）、只读环境检测脚本、部署章节 Markdown |
| `security.js` | 安全工具 | `maskSecret` 掩码、`redact`/`redactDocument` 脱敏、敏感模式库、命令风险扫描、文件名清洗、Base URL 校验 |
| `history.js` | 历史记录 | 20 条上限、同仓库去重、体积上限淘汰、懒加载、导出（不含密钥）、存储统计 |
| `markdown-view.js` | 轻量 Markdown 渲染 | 解析为结构块 + DOM API 构建，**全程不使用 `innerHTML`**，杜绝 XSS |
| `settings.js` | 设置与存储 | 默认值、读写、`setAccessLevel` 存储加固、清缓存 / 清全部数据 |
| `errors.js` | 错误模型 | 错误码 → 用户可读信息 + 可操作 `hint` + 是否可重试；错误详情经脱敏 |

## 消息协议（popup / 部署页 ⇄ background）

| 消息 | 方向 | 说明 |
|---|---|---|
| `GENERATE` | popup → SW | 生成解读，长任务走端口通道（`delta` 流式分片 + `progress` 进度 + `result` 结果） |
| `PREFETCH` | popup → SW | 打开弹窗时预热仓库元信息（1 次请求，命中缓存 0 次） |
| `TEST_LLM` | 设置页 → SW | 测试连接 |
| `GET_HISTORY` / `GET_HISTORY_ENTRY` / `DELETE_HISTORY` / `CLEAR_HISTORY` / `EXPORT_HISTORY` | popup / 设置页 → SW | 历史记录读写与导出 |
| `STORAGE_STATS` | 设置页 → SW | 存储占用、历史条数、缓存条数、密钥状态 |
| `CLEAR_CACHE` / `CLEAR_ALL` | 设置页 → SW | 清缓存 / 清全部本地数据 |
| `GET_ANALYSIS` | 部署页 → SW | 取当前分析结果（含风险与沙箱判定，**不含 README 全文**） |
| `BUILD_DEPLOY` | 部署页 → SW | 生成部署章节与脚本（可带环境预检 JSON） |
| `GET_INFLIGHT` | popup → SW | 检测上次生成是否被中断 |

## 数据存放位置

| 数据 | 位置 | 备注 |
|---|---|---|
| 设置（含 Key / Token） | `chrome.storage.local` → `settings` | 明文存储；已限制为仅扩展页面可读 |
| 仓库缓存 | `chrome.storage.local` → `ghcache:*` | 6 小时有效；私有仓库不写 |
| 历史记录 | `chrome.storage.local` → `history` | 最多 20 条；私有仓库默认不写 |
| 当前分析结果 | `chrome.storage.session` | 仅内存，浏览器重启即清空 |
| 生成中的请求状态 | `chrome.storage.session` → `inflight` | 用于判断上次是否被中断 |

## 打包

`tools/package.sh` 只打包扩展运行必需的文件，并在打包后自检：

1. 校验 `manifest.json` 合法；
2. 解析所有 HTML 的 `src`/`href` 与 JS 的 `import`，确认引用的文件都在包内；
3. 缺文件直接报错退出，避免出现「装上后功能打不开」。

```bash
bash tools/package.sh                 # 输出 repo-insight-<version>.zip
python3 tools/gen_icons.py            # 重新生成 16/48/128 图标
```

`tools/`、`docs/`、`.git` 等内容不会进入 zip。
