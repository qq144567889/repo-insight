# 安全与合规说明

本文件说明 Repo Insight 的安全设计、隐私边界与合规考虑。**它同时是给使用者与审核者的说明**，不含法律意见。

## 一、能力边界（先说清楚）

| 能力 | 有 / 无 | 说明 |
|---|---|---|
| 执行系统命令 | ❌ | Chrome MV3 的 Service Worker 没有 shell / `child_process`，「一键本地部署」只是**生成可运行脚本** |
| 读取本机环境 | ❌ | 通过**只读检测脚本 + 用户粘贴 JSON** 间接获得 |
| 静态规则风险评估 | ✅ | 文本规则匹配，可解释、可复现 |
| 运行时行为检测 | ❌ | 无法判断脚本实际会做什么，文档中已明确标注 |
| 代码级分析 / CVE 扫描 | ❌ | 不做 AST、不查依赖漏洞库 |
| 遥测 / 统计上报 | ❌ | 没有任何服务端 |

## 二、密钥处理

| 位置 | 处理方式 |
|---|---|
| 设置页回显 | 只显示 `sk-abc****wxyz` 形式的掩码；输入框留空表示不修改，另有「清除」按钮 |
| 日志 / 错误信息 | 统一走 `redact()`，抹除 `sk-`、`ghp_`、`github_pat_`、`AKIA`、Telegram / Slack Token、`Bearer`、私钥文件头，并清理 URL 中的敏感查询参数 |
| 生成的 Markdown | 输出前整篇 `redactDocument()`，README 里泄漏的密钥也会被打码 |
| 预览 / 复制 / 下载 | 共用同一份脱敏内容 |
| 历史记录入库 | 入库前脱敏 |
| 导出备份 | 导出时再次脱敏，且**不包含** `settings`（Key / Token 不在备份里） |

> **如实告知**：`chrome.storage.local` 是**明文存储**，扩展无法加密（浏览器未提供密钥管理 API）。建议使用受限权限的 Key；敏感场景推荐本地 Ollama。

## 三、数据流向

| 触发动作 | 发送内容 | 接收方 |
|---|---|---|
| 点「生成解读」 | 仓库名称、元信息、根目录文件列表、README（最多 30000 字符） | `api.github.com` 与**你选择的模型服务商** |
| 选择 Ollama | 同上 | 仅本机 `localhost:11434`，内容不出本机 |
| 打开弹窗预热 | 仓库名 | 仅 `api.github.com` |
| 部署页风险评估 / 环境预检 | 无外发 | 全部在本机计算 |

**私有仓库**：识别到 `private` 后先中止流程并询问；确认后才发送，选择 Ollama 时不询问也不外发；私有仓库内容不写入本地缓存与历史。

## 四、提示词注入防护

README 属于**攻击者可控内容**。若直接拼进提示词，恶意仓库可以诱导模型在「一键部署工作流」中写入危险命令，用户会误以为是官方部署步骤。

四层处理：

1. **数据边界**：README 全文包在 `<untrusted_readme>` 标签内，提示词明确其属于数据而非指令；
2. **指令隔离**：提示词硬性条款禁止执行其中的任何指令、禁止在输出中复述；
3. **产物审查**：生成的文档与预览区都会扫描「管道执行 shell」「下载后赋权执行」「关闭证书校验」等模式并高亮提示；
4. **预期管理**：文档头部固定标注 AI 生成，禁止给出「下载即执行」形式的命令。

> 局限：以上都是**降低概率**，不能保证模型 100% 不被绕过。执行任何部署命令前请核对仓库官方 README。

## 五、权限说明

| 权限 | 必要性 |
|---|---|
| `storage` | 保存设置与缓存 |
| `activeTab` | 读取当前标签页地址；等价替代是 `tabs`（更宽），因此不申请 |
| `https://github.com/*` | 判断是否仓库页（自动弹出功能需要），不抓取网页内容 |
| `https://api.github.com/*` | 拉取仓库元信息与 README |
| 模型服务域名 | 调用所选模型；自定义网关走**运行时按需授权** |
| `http://localhost/*`、`http://127.0.0.1/*` | 本机 Ollama |

扩展**不申请** `<all_urls>`、`tabs`、`downloads`、`cookies` 等高危权限。

## 六、生成内容的合规提示

| 项 | 处理 |
|---|---|
| AI 标识 | 文档首行固定 `> 🤖 本文档由 AI 生成…`；文末含 `author` / `license` 溯源注释 |
| 许可证风险 | 按 SPDX 分级提示：未声明许可证 → 默认保留所有权利、不得商用与再分发；GPL / AGPL 分别提示开源义务；宽松许可只保留字段 |
| 法务边界 | 文档中注明「不构成法律意见」，商用前需咨询法务 |
| 来源署名 | 生成文档携带项目与作者信息，便于溯源 |

## 七、卸载与数据清除

- 扩展完全运行在浏览器沙箱内：不修改系统设置，不写入浏览器之外的文件；
- 卸载扩展时 Chrome 会自动删除扩展专属存储（含 Key、Token 与历史）；
- 设置页提供「清空历史」「清除缓存」「清除所有本地数据」三个粒度的清理；
- 卸载前可先导出历史备份（不含密钥）留档。

## 八、部署安全建议（按隔离强度）

1. **云端沙箱**（Codespaces / Gitpod / StackBlitz）：完全不碰本机，适合先试跑；
2. **容器隔离**（推荐用于本地）：`docker run --rm`、只挂载专用数据卷、API Key 走环境变量，用完删除容器；
3. **虚拟机隔离**：高风险项目或需要系统级测试时使用；
4. **最小权限运行**：非 root 用户、专用目录、只授予必要权限。

生成的部署脚本默认走第 2 种，并提供 `--dry-run` 先预览将执行的命令。
